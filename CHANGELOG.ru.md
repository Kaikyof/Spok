## [Unreleased]

### Добавлено

- Подключение спеки команды по git-адресу или по пути к локальной копии: прогресс клонирования, отмена и понятные ошибки. Клонирование идёт вашим git — с вашими ssh-ключами и настройками.
- Шаг «Что распознано» перед первым открытием спеки: что приложение поняло из спеки, где это нашло и какие экраны от этого заработают.
- Экран «Группа»: change'и спринта, мастер-спеки или всей спеки по стекам — статусы Redmine, отметки задач, расхождения статуса с фактом и следующий шаг.
- Карточка change'а: спека изменения, чеклисты по стекам, артефакты схемы, зависимости, ветки и MR из GitLab с фактом влития, комментарии Redmine.
- Экран «Документы»: дерево спеки с артефактами change'ей и архивом, просмотр markdown и открытие файла в IDE.
- Экран «Окружение»: проверка ключей из `.env.example`, состояния репозиториев и доступности Redmine, GitLab и Mattermost; форма заполнения ключей с импортом из готового `.env`.
- Секреты хранятся в Keychain на macOS и в secret-tool на Linux, а без системного хранилища — в файле с правами 0600. `.env` спеки собирается из хранилища сам.
- Экран «Сессии»: диалоги с Claude Code в репозитории спеки — палитра команд спеки с подсказками аргументов, выбор модели, режима доступа и effort, markdown в ответах.
- Экран «Передача»: готовность с блокерами, сборки, выбор получателей и предпросмотр сообщения перед передачей стека.
- Панель запуска: последняя команда, код возврата, длительность и вывод с копированием.
- Функция, недоступная спеке, не пропадает, а объясняет, чего не хватает.
- Загрузка, частичные ошибки и устаревшие данные показываются внутри экрана, а «Повторить» и «Обновить» стоят рядом с сообщением.
- Поддержка проектов на оригинальном OpenSpec: схема `spec-driven` и задачи без стеков и трекера.
- Сборка под Linux; настройки и клоны спек лежат в стандартных каталогах системы.
- Описание релиза на GitHub собирается из этого журнала — на английском и русском.
- Стадия работы change'а из файлов спеки — планирование, готов к реализации, в работе, сделано, в архиве — в таблице группы и в шапке карточки; у спеки без стеков следующий шаг считается по стадии.
- После сессии по change'у предлагается шаг по его стадии: архивировать сделанный, продолжить планирование, реализовать готовый. Плашка следующего шага у сделанного change'а получила команду архивирования.
- Команды и скиллы читаются и из каталогов других инструментов — `.agents/skills`, `.opencode`, `.github/prompts`; копии одной команды показываются один раз.

### Изменено

- Статус трекера показывается ярлыком рядом со стадией, а не вместо неё; тексты приложения называют систему по имени из спеки, а не «Redmine». Спека без трекера не слышит «нет доступа» и «нет ключа».
- Экран «Окружение»: раздел ключей есть только при `.env.example`, внешние системы — только по объявленным в нём адресам.
- Аргументы команды без `argument-hint` берутся только из строки вызова в разделе `**Input**`. Команда, у которой там только проза, остаётся в палитре, а не попадает в меню карточки change'а.

### Исправлено

- Команды оригинального OpenSpec вызываются так, как их регистрирует Claude Code (`/opsx:propose`), а не по заголовку из файла (`/OPSX: Propose`); команда и скилл об одном и том же — одна строка палитры.
- Команда создания change'а больше не стоит в меню действий карточки; «Реализовать» и «Архивировать» появляются по назначению команды, даже без описания аргументов.
