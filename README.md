# Spok

Десктопное приложение (Flutter, macOS) — оболочка над спекой разработки
(openspec-репозиторием команды). Делает состояние работы видимым, а следующий
шаг — очевидным. Проверено на двух спеках: `avtoto-platform` (спринты, два
стека, сборки, мессенджер) и `avelacom-platform` (мастер-спеки, один стек,
без сборок и MR).

Бриф: `avtoto-platform/docs/platform-console-idea.md`.
Макеты: Penpot, страница «Platform Console» (имя страницы историческое —
приложение переименовано в Spok).

## Что уже работает

- **Группа** — таблица change'ей по стекам спеки: живые статусы Redmine
  (а при их отсутствии — закэшированные в `redmine.yaml` change'а, с пометкой
  «из файла»), отметки задач из `tasks_*.md`, блок расхождений (статус против
  факта), плашка следующего шага. Группа — спринт (`openspec/doc/<id>/sprint.yaml`),
  мастер-спека (`openspec/doc/<id>.md`) или просто все change'и спеки.
- **Change'и** — список и карточка. Главный текст карточки — спека изменения
  (`proposal.md`), под ней чеклисты по стекам, кнопка «Реализовать» и меню
  «Ещё действия» (команды, применимые к change'у по сигнатуре; выбранная
  подставляется в строку ввода сессии). Справа — артефакты из схемы спеки
  с порядком и подсказками по `requires`, зависимости, блок «Код» (ветки,
  MR из GitLab и факт влития коммита в целевую ветку; выключен — объясняет,
  чего не хватает: спека не работает с MR, ключ не заполнен у меня или
  хостинг не отвечает) и лента комментариев Redmine.
- **Документация** — рендер markdown (`proposal.md`, `design.md`,
  `tasks_*.md`) прямо в приложении.
- **Окружение** — наличие всех ключей `.env.example` (без значений) с
  подсказками из комментариев спеки, состояние репозиториев workspace
  (ветка, отставание), доступность Redmine/GitLab/Mattermost. Кнопка
  «Заполнить ключи» открывает форму: поля из `.env.example`, секреты
  маскированы, сохранение пишет `.env` спеки (чужие строки и комментарии
  сохраняются, пустое поле убирает ключ), при незакрытом `.gitignore`
  показывается предупреждение.
- Переключатель групп, смена спеки, индикатор свежести, обновление.

- **Передача** — четыре шага (или объяснение, почему передача недоступна
  этой спеке): готовность с блокерами, сборки, выбор
  получателей (скрипт платформы подбирает роли Redmine × канал Mattermost),
  предпросмотр сообщения и побочных эффектов; кнопка запускает
  `/opsx-sprint <sprint> handover --stack <stack>` в агентной сессии
  после подтверждения.
- **Новый спринт** — кнопка на экране «Спринт»: текст ТЗ или файл уходят
  в `/opsx-doc`, который создаёт мастер-спеку и файлы спринта.
- **Сессии** — агентные диалоги: запуск Claude Code headless-процессом
  в репозитории платформы (`claude -p --output-format stream-json`),
  продолжение диалога через `--resume`, создание и удаление сессий.
  Сессии выбираются выпадающим списком в заголовке ленты — вертикаль отдана
  диалогу и терминалу. Внизу экрана — терминал во всю ширину контента: вывод
  последней команды, одна строка ввода «команда + задание словами» (высота
  тянется мышью плавно)
  и параметры запуска под ней — модель, доступ, effort. Палитра всплывает
  по «/» или кнопкой «Все команды спеки»: у каждой команды видны сигнатура
  и источник (канон схемы · `.claude` · зеркало · `package.json` ·
  `Makefile`). Команда роли «реализовать» — выделенной кнопкой в заголовке, остальные
  роли под «Ещё»; после завершения сессии показываются следующие шаги. Смена спеки или группы
  перечитывает команды и подсказки аргументов. Модель, доступ, effort
  и высота терминала запоминаются по проекту; список моделей правится
  ключом `SESSION_MODELS` в конфиге приложения.
- **Панель запуска** — постоянная нижняя панель: последняя выполненная
  команда моноширинным, код возврата, длительность, разворачиваемый вывод
  и копирование команды и вывода.

Не реализовано (следующие этапы): секреты в системном хранилище (Keychain)
вместо `.env`, фактическая отправка передачи через
скрипты платформы, панель запуска команд, светлая тема.

## Как устроено

Приложение ничего не хранит и не вычисляет само: читает файлы спеки
(`workspace.yaml`, `.env`, `openspec/**`), опрашивает Redmine по API и
спрашивает git. Каждое обновление — полный пересбор слепка.

Устройство спеки не зашито в код, а читается из неё самой:

| Что | Откуда |
|---|---|
| стеки и имена файлов задач | `openspec/schemas/<schema>/schema.yaml` — артефакты `tasks-<stack>` |
| список артефактов change'а | там же, `artifacts[].generates` |
| имя ветки change'а | там же, `apply.instruction` |
| смысл статусов (работа / передача / закрыт) | `openspec/redmine.yaml` — `sync.*` и `statuses` |
| статусы конкретного change'а | `redmine.yaml` change'а (версии 3 и 4; иная версия помечается явно) |
| группировка | каталоги спринтов, иначе мастер-спеки `openspec/doc/*.md` |
| ключи окружения | `.env.example` целиком, подсказка — комментарий над строкой |

Фичи включаются по наличию данных: сборки — при `builds.yaml` группы, блок
«Код» — при `GITLAB_TOKEN` в `.env.example` и сервисах в `workspace.yaml`,
передача — при семантике статусов и группировке. Недоступная фича не исчезает,
а объясняет, чего не хватает; переключатель стеков не рисуется при одном стеке.

Путь к спеке: переменная окружения `SPEC_PLATFORM_DIR` (или
`AVTOTO_PLATFORM_DIR`), затем путь из конфига приложения
(`~/Library/Application Support/PlatformConsole/.env`, ключ
`AVTOTO_PLATFORM_DIR`), затем типовые пути. Сменить спеку можно прямо в
приложении — клик по названию спеки в левом верхнем углу.

## Архитектура

Clean Architecture, слои:

```
lib/
  core/            ресурсы (AppColors, AppTextStyles, AppDimens) и тема
  domain/          сущности, контракты репозиториев, usecases (FindDivergences)
  data/            sources (файлы платформы, Redmine API на dio) + repositories
  presentation/    bloc (event/state/bloc), shell, screens, ui_kit
  l10n/            строки интерфейса (gen-l10n, app_ru.arb)
```

Правила стиля: тексты — только через локализацию (домен возвращает
структуры, форматирует presentation); подписка на блок — BlocBuilder;
виджеты — классами; каждый класс — отдельный файл (кроме приватных
виджетов); переиспользуемые компоненты — в `presentation/ui_kit`.

Стек: flutter_bloc, dio, get_it, intl, path, yaml, flutter_markdown_plus
(маинтейнящийся форк flutter_markdown с тем же API), window_manager.
auto_route и json_serializable подключим, когда появятся глубокие маршруты
(карточка change по id) и DTO-модели GitLab/Mattermost.

## Запуск

```bash
flutter run -d macos
```

Смоук данных без UI (печатает слепок по реальным файлам спеки):

```bash
dart run tool/smoke.dart
SPEC_PLATFORM_DIR=~/avelacom-platform dart run tool/smoke.dart
```
