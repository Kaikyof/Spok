## Purpose

Запуск агентной сессии через установленный на машине инструмент — Claude
Code, Codex, Gemini CLI, OpenCode — с выбором инструмента и формой вызова
команд спеки, понятной этому инструменту.

## ADDED Requirements

### Requirement: Несколько агентных инструментов

Приложение SHALL запускать сессии через любой поддерживаемый инструмент,
найденный на машине, и показывать в ленте его события в общем виде.

#### Scenario: Codex вместо Claude Code
- **WHEN** на машине нет `claude`, есть `codex`, проект инициализирован для
  Codex (`.agents/skills/openspec-*`)
- **THEN** сессия запускается через `codex exec`, лента показывает текст и
  вызовы инструментов, после завершения — следующие шаги

#### Scenario: Ни одного инструмента
- **WHEN** ни один поддерживаемый инструмент не найден
- **THEN** экран «Сессии» объясняет, какие инструменты поддерживаются и
  как их установить, без пустого экрана

### Requirement: Выбор агента по проекту

Приложение SHALL предлагать по умолчанию инструмент, для которого проект
инициализирован, и запоминать выбор по проекту рядом с моделью и effort.

#### Scenario: Проект для Claude и Codex
- **WHEN** в проекте есть `.claude/` и `.agents/`, на машине оба инструмента
- **THEN** селектор предлагает оба, по умолчанию Claude Code; выбор
  сохраняется для проекта

### Requirement: Форма вызова по инструменту

Палитра SHALL подставлять команду в форме, которую регистрирует выбранный
инструмент: `/opsx:<id>` для Claude Code, `/opsx-<id>` для Cursor,
`$openspec-<skill>` для Codex.

#### Scenario: Та же команда, разные агенты
- **WHEN** человек выбирает `propose` при агенте Codex
- **THEN** в строку ввода подставляется `$openspec-propose`

### Requirement: Инструмент без headless-режима

Для инструмента без запуска из командной строки приложение SHALL
предлагать «Скопировать команду» вместо запуска сессии.

#### Scenario: Cursor
- **WHEN** выбран Cursor
- **THEN** кнопка запуска заменена на «Скопировать команду», строка
  скопирована в буфер обмена, сессия не создаётся
