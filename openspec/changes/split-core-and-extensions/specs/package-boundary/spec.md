## Purpose

Граница между ядром приложения, работающим с любой спекой на OpenSpec, и
расширениями, которые знают о трекерах, хостингах и мессенджерах; что
обязано собираться отдельно и что проверяет CI.

## ADDED Requirements

### Requirement: Ядро собирается без расширений

Пакет ядра SHALL проходить анализ и тесты сам по себе, без зависимостей
на пакеты расширений.

#### Scenario: Прогон в каталоге ядра
- **WHEN** CI выполняет `flutter analyze` и `flutter test` в `packages/spok_core`
- **THEN** оба завершаются успешно без пакетов `spok_ext_*` в зависимостях

### Requirement: Ядро не называет внешних систем

Исходный код ядра SHALL не импортировать пакеты расширений и не содержать
имён конкретных систем (`redmine`, `gitlab`, `mattermost`), кроме тестовых
фикстур.

#### Scenario: Импорт адаптера в ядро
- **WHEN** в файл ядра добавлен импорт из `spok_ext_tracker_redmine`
- **THEN** проверка границы в CI завершается ошибкой с именем файла

### Requirement: Приложение без активных расширений

При отсутствии улик всех расширений приложение SHALL показывать интерфейс
только ядра.

#### Scenario: Навигация на фикстуре upstream
- **WHEN** виджет-тест открывает фикстуру оригинального OpenSpec
- **THEN** навигация содержит ровно три пункта, тексты экранов не содержат
  имён внешних систем

### Requirement: Сборка с выбранным набором расширений

Приложение SHALL позволять ограничить регистрируемые расширения флагом
сборки; по умолчанию регистрируются все.

#### Scenario: Сборка только ядра
- **WHEN** приложение собрано с `--dart-define=SPOK_EXTENSIONS=core`
- **THEN** на avtoto интерфейс тот же, что на проекте без улик
