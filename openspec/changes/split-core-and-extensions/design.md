## Context

Один пакет `spok`; расширения после этапа 4 — в `lib/extensions/`; одна
локаль `lib/l10n/app_ru.arb`, `l10n.yaml` в корне; CI — `linux.yml`
(analyze, test). См. proposal.md и план, 4.6–4.7.

## Goals / Non-Goals

Goals: граница ядра проверяется машиной; репозиторий проходит чеклист
4.7.2–4.7.6 плана; английский интерфейс.
Non-Goals: новые экраны (настройки, тема, первый запуск — `add-light-theme-and-settings`),
Windows и дистрибуция (`add-windows-and-distribution`).

## Decisions

- **Раскладка**: `packages/spok_core` (domain + data ядра, свои тесты,
  свой `l10n`), `packages/spok_ext_{tracker_redmine,workspace,code_gitlab,chat_mattermost,sprints}`,
  `lib/` — `main.dart`, регистрация, shell, тема. Публикация в pub не
  планируется — `path`-зависимости.
- **Проверка границы — тремя дешёвыми вещами**: отдельный прогон в
  `spok_core`; `tool/check_core_boundary.dart` (импорты и слова, кроме
  `test/fixtures`); виджет-тест «три пункта навигации». Всё в
  `linux.yml`.
- **Локализация по пакетам** — `flutter gen-l10n` на пакет, приложение
  собирает делегаты всех пакетов в `localizationsDelegates`. Первый пакет
  проверяет, что делегаты не конфликтуют по классу. Строки ядра — с
  плейсхолдером `{tracker}` там, где раньше было имя.
- **Английский — язык по умолчанию** (`supportedLocales: [en, ru]`, `en`
  первым); `locale` из системы; принудительный выбор — в настройках
  (следующий change). Перевод — по `app_ru.arb` как источнику смысла, с
  проверкой терминов: change, spec, stage, tracker, extension.
- **Тест паритета** — все локали всех пакетов имеют одинаковые наборы ключей.
- **Гигиена**: `gitleaks detect` на полном клоне до публичного пуша (не
  в CI — история может содержать секреты, о которых узнать надо до
  публикации); `git filter-repo` при находке.
- **Идентификатор** — решение команды; по умолчанию оставить
  `ru.webant.spok`, потому что смена после релиза ломает каталог данных и
  связку ключей.
- **«О приложении»** — `showAboutDialog` с `LicenseRegistry` и версией из
  `package_info_plus`.

## Risks / Trade-offs

- [Делегаты локализации нескольких пакетов] → проверить на первом
  пакете; при конфликте — единый `.arb` в ядре с префиксами ключей.
- [Перевод 400+ строк вручную] → параллельная задача; черновик машинным
  переводом, вычитка человеком по терминам.
- [Переезд файлов ломает историю blame] → `git mv`, один коммит на
  переезд без правок содержимого.

## Migration Plan

1. Переезд файлов в пакеты без правок (`git mv`), сборка.
2. Локализация по пакетам, английский.
3. Файлы сообщества и документы.
4. Гигиена и «О приложении».
Откат любого шага — возврат коммита.
