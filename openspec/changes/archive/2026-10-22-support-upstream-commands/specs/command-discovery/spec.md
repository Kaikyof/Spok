## Purpose

Как приложение собирает команды спеки из файлов агентов, называет вызов,
склеивает дубли из разных каталогов и решает, где команда показывается.

## ADDED Requirements

### Requirement: Имя вызова из пути файла

Для команды в `commands/<ns>/<id>.md` приложение SHALL использовать вызов
`/<ns>:<id>`, для `commands/<id>.md` — `/<id>`; поле `name` из frontmatter
SHALL использоваться только если оно похоже на вызов (начинается с `/` или
не содержит пробелов и заглавных букв).

#### Scenario: Команда, сгенерированная upstream
- **WHEN** в проекте есть `.claude/commands/opsx/propose.md` с
  `name: OPSX: Propose`
- **THEN** в палитре команда `/opsx:propose`, и в сессию уходит
  `/opsx:propose <текст>`

#### Scenario: Команда спеки команды
- **WHEN** в avtoto есть `.claude/commands/opsx-apply.md` с `name: /opsx-apply`
- **THEN** вызов — `/opsx-apply`, как до этого change'а

### Requirement: Скилл склеивается с командой

Если описание скилла называет команду фразой `"opsx <id>"` и команда с таким
id найдена, приложение SHALL показывать их одной строкой палитры; иначе
скилл SHALL оставаться самостоятельной командой с вызовом по имени скилла.

#### Scenario: Пара скилл и команда
- **WHEN** есть `.claude/skills/openspec-propose/SKILL.md` с описанием,
  содержащим `"opsx propose"`, и `.claude/commands/opsx/propose.md`
- **THEN** в палитре одна строка `/opsx:propose`

#### Scenario: Только скиллы
- **WHEN** проект инициализирован без команд, есть только
  `.claude/skills/openspec-*/SKILL.md`
- **THEN** в палитре команды `/openspec-propose`, `/openspec-apply-change` и
  остальные скиллы

### Requirement: Применимость без описания аргументов

Без `argument-hint` приложение SHALL определять применимость команды по
строке вызова в разделе `**Input**`, затем по роли команды; при их
отсутствии команда SHALL показываться только в палитре.

#### Scenario: Команда создания change'а
- **WHEN** у `/opsx:propose` нет `argument-hint`, а в `**Input**` только проза
- **THEN** команда есть в общем меню и палитре, но не в меню действий
  карточки change'а

#### Scenario: Команда реализации
- **WHEN** у `/opsx:apply` нет `argument-hint`
- **THEN** по роли `apply` команда становится кнопкой «Реализовать» на
  карточке change'а

### Requirement: Роль архивирования

Приложение SHALL распознавать роль `archive` по имени команды и
использовать её в следующих шагах после сессии и в плашке следующего шага
для change'ей в стадии `done`.

#### Scenario: Завершённая сессия по сделанному change'у
- **WHEN** сессия завершилась, change в стадии `done`, у спеки есть
  `/opsx:archive`
- **THEN** среди следующих шагов есть «Архивировать» с этой командой

### Requirement: Каталоги других агентов

Приложение SHALL читать команды и скиллы из каталогов инструментов, которые
генерирует upstream (`.claude`, `.agents/skills`, `.cursor`, `.opencode`,
`.github/prompts` и другие с файлами `.md`), склеивая дубли по
нормализованному id.

#### Scenario: Проект для трёх инструментов
- **WHEN** `openspec init --tools claude,cursor,opencode`
- **THEN** в палитре каждая команда один раз, источник — первый по
  приоритету каталог
