## Context

`loadDocTree` строит узлы «группа → change → одиночные артефакты + прочие
`.md` в корне change'а»; маски (`specs/**/*.md`) отбрасываются. См.
proposal.md.

## Goals / Non-Goals

Goals: спецификации и дельты видны и читаются тем же рендером markdown.
Non-Goals: разбор требований и сценариев в структуру, сравнение дельты с
основной спецификацией (это делает `openspec show`, см. этап 7).

## Decisions

- **Узел «Спецификации» — верхнего уровня, после групп, перед архивом.**
  `DocNodeKind.specs`; дети — по каталогам `openspec/specs/**`, лист —
  `spec.md`; заголовок листа — из H1 файла, иначе имя каталога.
- **Дельты change'а — раскрытая маска.** Для артефакта с маской
  `_changeDocs` добавляет по `DocArtifact` на каждый найденный файл с
  `id: '<artifact>:<relative path>'`; пометка операции — первые заголовки
  `## ADDED|MODIFIED|REMOVED|RENAMED Requirements` в файле, показывается
  подписью рядом с именем.
- **Артефакт-маска без файлов** у активного change'а — одна серая строка
  «объявлен схемой, файлов нет» (как у одиночных); у архивного — не
  показывается.

## Risks / Trade-offs

- [Большие каталоги спецификаций замедлят построение дерева] → чтение
  заголовков лениво при раскрытии узла; на клоне upstream 30+ файлов —
  приемлемо и так.
