## Purpose

Хостинг кода как порт приложения: запрос на слияние по ветке change'а,
факт влития, ссылка на ветку и доступность системы — одинаково для GitLab,
GitHub и следующих систем.

## ADDED Requirements

### Requirement: Запрос на слияние по ветке независимо от системы

Для change'а с объявленной веткой приложение SHALL показывать состояние
запроса на слияние (открыт, влит, нет) и факт влития коммита в целевую
ветку через контракт хостинга; система определяется адаптером по улике.

#### Scenario: Проект на GitHub
- **WHEN** проект с remote на github.com, `GITHUB_TOKEN` заполнен, у
  change'а есть ветка с открытым pull request
- **THEN** блок «Код» показывает pull request со ссылкой и состоянием
  «открыт»

#### Scenario: Спека на GitLab
- **WHEN** открыт avtoto с заполненным `GITLAB_TOKEN`
- **THEN** блок «Код» показывает MR, как до этого change'а

### Requirement: Ссылка на ветку собирается адаптером

Адрес страницы ветки SHALL формировать адаптер конкретной системы; ядро не
знает формата адреса.

#### Scenario: GitHub и GitLab
- **WHEN** ветка `features/x` в проекте на GitHub и в проекте на GitLab
- **THEN** ссылки — `…/tree/features/x` и `…/-/tree/features/x`
  соответственно

### Requirement: Улика хостинга

Расширение хостинга SHALL активироваться по ключу токена системы в
`.env.example` или по адресу remote репозитория проекта.

#### Scenario: Remote без ключей
- **WHEN** `.env.example` нет, а `git remote get-url origin` указывает на
  github.com
- **THEN** расширение GitHub активно с требованием `personal` «токен не
  заполнен» и ссылкой на ветку без токена
