## Context

`AppTheme.dark()` — единственная тема; цвета — токены в `AppColors`;
конфиг — `AppConfigSource` с ключами в `.env` каталога приложения;
подключение — `SetupScreen` с полем URL или пути. См. proposal.md и план,
4.7.1.

## Goals / Non-Goals

Goals: обе темы, настройки в интерфейсе, первый запуск для новичка,
доступность на ключевых экранах. Non-Goals: пользовательские темы,
синхронизация настроек между машинами.

## Decisions

- **Темы** — `AppTheme.light()` и `AppTheme.dark()` из одних токенов
  `AppColors` с двумя наборами значений; `ThemeMode.system` по умолчанию.
  Цвета стадий и статусов проверяются на контраст ≥ 4.5:1 на обоих фонах
  тестом. Принцип «цвет не единственный носитель смысла» сохраняется —
  форма точки и подпись остаются.
- **Настройки** — экран в приложении, читает и пишет `AppConfigSource`;
  файл остаётся источником; неизвестные ключи файла не трогаются.
- **Первый запуск** — `SetupScreen` получает три состояния каталога:
  спека (как сейчас), каталог без `openspec/` (предложение `openspec init`
  при найденном CLI, ссылка на upstream), пустой выбор (пример проекта —
  `test/fixtures/upstream-sample`, скопированный в каталог данных).
- **Доступность** — `Semantics` с label у строк таблицы (стадия, статус
  словами), `FocusTraversal` по экранам, `MediaQuery.textScaler`
  соблюдается, `meetsGuideline(textContrastGuideline)` в тестах ключевых
  экранов.

## Risks / Trade-offs

- [Светлая палитра потребует дизайнера] → макет обеих тем до реализации;
  автоматическая инверсия не годится.
- [Экран настроек — новый борд] → в `design-plan.md` очередь 3.

## Migration Plan

Настройки читаются из существующего файла; новых ключей — `THEME`,
`LOCALE`, `AGENT`.
