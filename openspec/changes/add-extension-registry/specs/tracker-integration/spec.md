## ADDED Requirements

### Requirement: Категории статусов объявляются, а не угадываются

Контракт трекера SHALL отдавать семантику статусов явными категориями
(`working`, `review`, `handoff`, `testing`, `closed`), объявленными в файле
спеки; вывод категорий из имён статусов по словам допускается только внутри
адаптера Redmine как запасной путь для `openspec/redmine.yaml`.

#### Scenario: Спека Redmine без явных категорий
- **WHEN** открыт avtoto с `openspec/redmine.yaml`, где есть только
  `sync.*` и список статусов
- **THEN** категории те же, что давали регулярки до этого change'а, и
  расхождения не изменились

### Requirement: Идентификатор задачи — строка

Контракт трекера SHALL работать со строковым идентификатором задачи с
адресом; числовые идентификаторы Redmine остаются строками из цифр.

#### Scenario: Ссылка на задачу Redmine
- **WHEN** у стека `issue_id: 63637`
- **THEN** ссылка ведёт на `<REDMINE_URL>/issues/63637`, текст — `#63637`

### Requirement: Файл объявления трекера

Приложение SHALL считать улику трекера найденной при наличии
`openspec/tracker.yaml` с полем `kind` или файла, эквивалентного для
конкретной системы (`openspec/redmine.yaml` для Redmine); ключи
`.env.example` уточняют личные требования, но сами по себе трекер не
объявляют, если файл объявления отсутствует и ключей адреса нет.

#### Scenario: Объявление через tracker.yaml
- **WHEN** в спеке есть `openspec/tracker.yaml` с `kind: redmine`
- **THEN** расширение трекера активно и использует адаптер Redmine
