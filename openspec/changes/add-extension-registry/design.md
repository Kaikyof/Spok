## Context

Фичи включаются через `ProjectProfile.features: Map<SpecFeature, FeatureGate>`;
навигация в `shell.dart` перечислена явно с гейтом у пункта; экраны
`handoff_screen`, `change_screen` (блок «Код») рендерят
`FeatureUnavailableView` при недоступном гейте; разбор спеки — шесть
фиксированных строк. См. proposal.md и раздел 4 плана.

## Goals / Non-Goals

Goals: расширение — единица кода и интерфейса, включаемая уликами; ядро не
знает о расширениях; avtoto и avelacom не меняются, кроме переезда кнопок
«Скопировать шаблон» в настройки и ветки спеки в шапку.

Non-Goals: разнос по пакетам (этап 6), вторые адаптеры (этап 9); здесь
расширения живут в `lib/extensions/` того же пакета.

## Decisions

- **Контракт** — абстрактный класс `SpecExtension` (см. план, 4.3).
  Вклады — списки объектов-описаний (`NavItem`, `ChangeCardBlock`,
  `GroupColumn`, `RecognizedItem`, `EnvSystem`, `DivergenceRule`,
  `CommandRole`), а не виджеты напрямую: ядро строит виджеты из описаний,
  расширение отдаёт данные и builder. Так ядро остаётся владельцем макета.
- **Активация — двухступенчатая.** `detect(files)` → `ExtensionEvidence`
  (список найденных улик с путями); нет ни одной — расширение неактивно и
  в интерфейсе отсутствует. Есть — `gate(files, env)` даёт `FeatureGate`
  как сегодня, и экраны показывают чеклист при невыполненных требованиях.
  Это и есть правило «скрыть или объяснить»: граница проходит по уликам,
  а не по требованиям.
- **Загрузка изолирована.** `load()` каждого расширения выполняется
  параллельно с ядром через `Future.wait` с `catchError`; отказ одного
  расширения — его `ExtensionData.failed(reason)`, экран показывает
  «недоступно с причиной», слепок ядра не страдает.
- **Порядок работ — по одному расширению**, начиная с трекера (порт уже
  есть после этапа 2): `tracker-redmine` → `workspace` → `code-gitlab` →
  `chat-mattermost` → `sprints`. После каждого — эталон avtoto.
- **`sprints` зависит от `tracker` и `workspace`** через `dependsOn`;
  реестр активирует расширение только при активных зависимостях, иначе
  показывает его в «Расширениях» как «ждёт: трекер».
- **Порты «с расчётом на второй адаптер»** (план 4.8), делаются здесь,
  чтобы этап 9 не переделывал ядро: `StatusSemantics.categories`
  (`working · review · handoff · testing · closed`) — явные, адаптер Redmine
  заполняет их из `redmine.yaml` (`sync.*`) и регулярок; `IssueRef`
  (`String value`, `Uri? url`) вместо `int issueId`; `Tracker.declarationFile`
  — `openspec/tracker.yaml` с `kind`, `openspec/redmine.yaml` — эквивалент
  для Redmine; `CodeHosting.branchUrl` в адаптере; `Chat.send` / `Chat.recipients?`.
- **«Окружение» в навигации** только когда хотя бы один раздел активен:
  ключи (`.env.example`), репозитории (`workspace`), системы (расширения).
  Ветка и отставание репозитория спеки — в шапке у чипа проекта.
- **Раздел «Расширения» в настройках проекта** — первый экран настроек
  (борд 13 в `design-plan.md`, очередь 3): список расширений со
  состоянием (активно / неактивно / ждёт зависимость), уликами (что
  искали, где), требованиями, кнопками «Скопировать шаблон» и «Создать
  через агента» из `assets/extensions/<id>.md`.

## Risks / Trade-offs

- [Самый большой этап; регрессия на avtoto] → по одному расширению,
  эталон после каждого; без живых спек не начинать.
- [Правило «скрыть» противоречит части 4.8 сводного документа] →
  зафиксировано в плане как изменение принципа; для avelacom поведение
  сохранено через улику сервисов.
- [Композиция вкладов усложнит экраны] → вклады — описания, порядок задан
  реестром; тест на состав навигации для трёх фикстур.

## Migration Plan

Поэтапно, по расширению; после каждого — `flutter test` и эталоны.
`SpecFeature` удаляется последним коммитом этапа.
