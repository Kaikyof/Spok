## Purpose

Как собранное приложение попадает к человеку на трёх системах и как он
узнаёт о новой версии.

## ADDED Requirements

### Requirement: Релиз по тегу

Публикация тега `v*` SHALL собирать приложение для macOS, Linux и Windows и
выкладывать артефакты в GitHub Releases с записью из `CHANGELOG`.

#### Scenario: Тег v0.2.0
- **WHEN** в репозиторий отправлен тег `v0.2.0`
- **THEN** в релизе есть `.dmg`, AppImage и MSIX, описание — раздел
  `0.2.0` из `CHANGELOG.md`

### Requirement: Установка без предупреждений на macOS

Артефакт macOS SHALL быть подписан и нотаризован, а установка через
Homebrew cask SHALL работать одной командой.

#### Scenario: Первый запуск на macOS
- **WHEN** человек открывает `.dmg` из релиза
- **THEN** Gatekeeper не показывает предупреждения о неизвестном
  разработчике

### Requirement: Проверка обновлений по кнопке

Приложение SHALL проверять наличие новой версии только по действию
человека и показывать ссылку на релиз; фоновых запросов SHALL не быть.

#### Scenario: Есть новая версия
- **WHEN** человек нажимает «Проверить обновления» и на GitHub есть релиз
  новее
- **THEN** показаны номер версии и ссылка на релиз

#### Scenario: Без действия человека
- **WHEN** приложение работает час без нажатия
- **THEN** запросов к GitHub Releases не было
