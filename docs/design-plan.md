# План по дизайну — что довести в коде

Чеклист по бордам Penpot (страница «Platform Console», 34 борда).
Сверка на 23.09.2026, подробности по каждому борду — в
`platform-console-master.md`, «Приложение А».

Пометки: `[x]` сделано · `[~]` частично, в скобках чего не хватает ·
`[ ]` не начато. Очереди — порядок работ, внутри очереди пункты
независимы.

Тот же объём работ, разрезанный по фичам продукта, а не по бордам, —
в `feature-plan.md`: удобно, когда берёшь фичу целиком.

## Очередь 1. Карточка change и меню действий · борды 02, 02b, 18 — сделано

Ежедневный экран разработчика; применимость команд выводится из сигнатуры
(`CommandScope`). Осталось только покрытие тестами — оно переехало
в очередь 5, вместе с разбором тест-кейсов.

- [x] спека изменения (`proposal.md`) — главный текст карточки, задачи
      и код под ней; «Открыть целиком» ведёт в просмотр документа
- [x] меню «Ещё действия» рядом с «Реализовать» — команды, применимые
      к change'у по сигнатуре, с подписью описания из спеки; выбор
      подставляет команду с известными аргументами в строку ввода сессии
- [x] вид «Применимых команд нет» — кнопка не показывается вовсе (борд 18)
- [x] полнота артефактов по `requires` схемы: порядок по зависимостям,
      строка «ждёт: <артефакт>» у тех, чьи предшественники пусты
- [x] строка артефакта «объявлен схемой, файла нет» — серая, с пометкой
- [x] блок «Код» в выключенном виде, три текста по природе нехватки:
      спека не работает с MR · токен не заполнен у меня (кнопка «Заполнить»)
      · хостинг не отвечает (401, «Проверить снова» / «Изменить ключ»)
- [x] ссылка «Открыть ветку в GitLab» без API — из адреса и имени ветки

## Очередь 2. Состояния данных · борды 19, 18 — сделано

Контракт на то, как экран ведёт себя, когда часть источников молчит.
Шесть видов — внутри экрана, а не вместо него.

- [x] скелет загрузки с сохранением раскладки — `SkeletonLine`/`SkeletonRow`,
      таблица группы и проверки окружения той же высоты и в тех же местах
- [x] частичная ошибка: «Статусы трекера недоступны — показаны данные
      файлов спеки» + «Повторить» рядом; строки помечены «из файла»,
      точка статуса полая
- [x] «данные устарели» мягкой подсветкой и кнопка «Обновить» рядом
      с самой пометкой, а не в другом углу шапки
- [x] «не распознано»: `SpecRecognition` — что поняли, чем именно и где
      искали, плюс «Указать вручную» (до очереди 3 ведёт на экран
      подключения спеки, потом — в настройки проекта)
- [x] пусто с объяснением и первым шагом: «Создать change»,
      «Открыть мастер-спеку» и превью команды, которая запустится
- [x] «нет доступа — ключ не заполнен у меня»: `MissingKeyBlock` — поле
      прямо в блоке, без похода в форму ключей за одним токеном
- [x] прогресс длинной операции: процент, неопределённый, ошибка,
      отмена рядом всегда — `ProgressPanel`, один на приложение
      (нужен очереди 3)

## Очередь 3. Подключение проекта и настройки · борды 08–10, 13, 13b

Самый объёмный кусок; закрывает этап 2 плана и часть этапа 3.

- [x] шаг 1 «Адрес репозитория»: одно поле на git-URL и локальный путь,
      подсказка под ним говорит, что произойдёт — скачивание или открытие
      каталога; клонируем git'ом человека, его ключами
- [x] шаг 2 «Клонирование»: `ProgressPanel` со сквозным процентом всей
      работы (этапы git разложены по участкам полосы, назад она не едет),
      объёмом и скоростью от git, живой вывод, «Отменить» рядом,
      человеческий текст

      `Authentication failed`, каталог занят, нет репозитория, нет сети,
      нет git). Оценки времени нет: git её не даёт, а выдумывать нельзя
- [ ] шаг 3 «Что распознано»: карточки группировки, стеков, статусов,

- [ ] экран «Настройки проекта»: путь клона, «Перечитать спеку», правка
      стратегии группировки, статусов и списка стеков

- [ ] таблица всех команд спеки: команда · сигнатура · где показывается ·
      роль · скрыть; строка «сигнатура не распознана — остаётся в палитре»
