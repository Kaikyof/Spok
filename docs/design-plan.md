## Сделано

- [x] **Окружение: импорт `.env` и команда раздела.** Ключи переносятся
      из готового файла другого проекта — значения подставляются в поля,
      но не сохраняются сами: в чужом файле бывают не те ключи, и те, что
      спека не спрашивает, названы поимённо. Описание ключа в форме больше
      не обрывается многоточием — оно вынесено отдельной строкой во всю
      ширину, потому что это единственное место, где спека объясняет,
      что за ключ и где его взять. У каждого раздела окружения появилась
      кнопка с командой самой спеки (`pnpm workspace:init`, `make init` —
      что распознано, то и показано; нет такой команды — нет и кнопки).
- [x] **Передача без команды передачи.** У спеки, которая передачу не
      описывает (avelacom), экран открывался как рабочий: команда передачи
      считалась необязательным требованием. Человек доходил до предпросмотра
      и кнопки, которая запустила бы `/opsx-sprint … handover` — команду
      чужой спеки, у этой не существующую. Теперь команда — обязательное
      требование: нет её, и фича выключена с чеклистом. А там, где она есть,
      строка команды собирается из её сигнатуры, а не из зашитого образца.
- [x] **Фидбэк наведения.** Нажимаемые строки, карточки и триггеры меню
      не отвечали на мышь ничем: `InkWell` рисует чернила на ближайшем
      `Material`, а он лежит за непрозрачным фоном карточки — подсветки
      не видно вовсе. Появился `Tappable`: курсор-палец и своя плёнка
      поверх содержимого (`foregroundDecoration`), для ссылок внутри
      текста — подчёркивание. Кнопкам Material подсветка задана в теме:
      своя, потому что стандартные 8 % от цвета текста на тёмном фоне
      неразличимы. Выключенное место не подсвечивается и курсор не меняет —
      наведение не обещает того, чего не будет.
- [x] **Передача без статусов трекера.** Экран доступен без ключей — и это
      правильно: получателей и сборку человек собирает без трекера. Но шаг
      «Готовность» считал готовым всякий стек, о статусе которого ничего не
      знал: проверка пропускалась, когда статуса нет ни живого, ни из кэша
      спеки, — и человек видел «1 из 1 готовы, блокеров нет». Теперь
      неизвестный статус — блокер `statusUnknown`, шаг получает четвёртое
      состояние «Готовность неизвестна» с причиной (ключ не заполнен у меня —
      поле прямо в шаге; трекер молчит — «Повторить»), а отправка выключена
      с той же причиной вместо «готовность 0 из 1».
- [x] **10 — шаг «Что распознано».** Подключение больше не отдаёт человека
      сразу экранам: сначала он видит, что приложение поняло в чужой спеке —
      шесть частей разбора со значением и местом поиска, нераспознанное
      названо словами, и матрица «что будет работать» с причиной у каждой
      выключенной фичи. «Изменить» открывает файл спеки, по которому часть
      разобрана: источник правды — сама спека, а настройка поверх неё ждёт
      «Настроек проекта».
- [x] **Прокрутка карточки change'а.** Спека жила в своём окне высотой 420
      внутри прокрутки страницы — и это был тупик: докрутив спеку, человек
      упирался, страница дальше не шла. Вложенные прокрутки во Flutter не
      передают колесо наружу (сигнал забирает самый внутренний список и,
      дойдя до края, молчит). Прокрутка на странице теперь одна, а длинная
      спека складывается с «Развернуть здесь» и растворяющимся нижним краем.
- [x] **19, 18 — состояния данных.** Скелет загрузки вместо лоадера
      в центре; частичная ошибка трекера с «Повторить» и полой точкой
      статуса; «данные устарели» с «Обновить» рядом; честный список
      разбора спеки с «Указать вручную»; пусто с двумя первыми шагами
      и превью команды; компактный блок «ключа нет только у меня»
      с полем; общий `ProgressPanel` для длинных операций.
- [x] **06, 06b — экран «Документы».** Дерево «группа / change / файл»
      слева, рендер markdown справа; мастер-спека одним файлом — документ
      самой группы; архив отдельным узлом с датой из имени каталога
      и очищенным id; строка «объявлен схемой, файла нет» у ненаписанных
      артефактов; «Открыть в IDE» и состояние файла в ветке спеки.
- [x] **05, 05b, 05c, 05d — сессии и терминал.** Сессии выпадающим списком
      в заголовке ленты; терминал
      внизу во всю ширину: вывод последней команды, единая строка
      «команда + задание словами», плавно тянущаяся высота, параметры
      запуска под полем; быстрый запуск — одна выделенная кнопка роли
      и «Ещё» с остальными; палитра с сигнатурой, источником и счётчиком
      отбора; следующие шаги после завершения. Настройки — по проекту.
- [x] **01, 01b, 01c — таблица группы** во всех вариантах по числу стеков,
      признак «статус из кэша», плашка следующего шага, расхождения.
- [x] **07, 07b — шапка**: подпись селектора по стратегии группировки,
      свежесть данных, переключатель спек.
- [x] **12 — диагностика выключенной фичи**: чеклист требований, три
      природы нехватки, счётчик в навигации.
- [x] **11 — форма ключей** (ввод и маскирование секретов, запись `.env`).
- [x] **Навигация**: приглушённый пункт со счётчиком невыполненных

## Открытые вопросы

**Передача стека, у которого нет сборок.** Сейчас `builds.yaml` группы —
единственный признак: он пуст — сборки не требуются ни одному стеку, он
заполнен — требуются каждому видимому, и стек без записи получает блокер
`buildMissing`. Оба правила грубые. Бывает backend, которому собирать
нечего, рядом с ios и android, которым есть; бывает стек, сборка которого
живёт вне спеки. Что делать — не решено:

- считать нужным сборку только тем стекам, которые уже появлялись
  в `builds.yaml` этой группы раньше (история вместо объявления);
- дать спеке объявить это прямо — `stacks.<stack>.builds: false` в схеме
  или в `builds.yaml`, и тогда правило станет её, а не нашим;
- спрашивать человека один раз на стек и запоминать в настройках проекта.

Пока экран ведёт себя по первому правилу — «есть `builds.yaml` → нужна
сборка каждому», — и это видно на avelacom: сборок нет ни у кого, шаг
«Сборка» гаснет целиком. Выбор требует живого примера спеки со смешанными
стеками; до него правило не меняем, чтобы не заменить одну догадку другой.

## Не делаем

**Молчаливое принятие расходящегося клона.** Спека, склонированная по тому
же адресу, но с локальными коммитами, не обновится: `git pull --ff-only`
откажется, и экран покажет это ошибкой с сообщением git. Принимать такой
клон с предупреждением не будем — расхождение веток человек должен
разобрать сам, а не узнать из мелкого шрифта под таблицей.

Блок «Агент ждёт решения» (борд 05): headless-CLI не размечает вопрос
агента, распознавать его по тексту ответа — угадывание. Вернуться, если
в `stream-json` появится признак ожидания ввода.
