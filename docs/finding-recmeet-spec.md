# Падение на спеке RecMeet: разбор и варианты решения

Документ для принятия решения. Что нашли, на каких данных, как перепроверить
и какие есть варианты с их ценой.

Дата разбора: 2026-09-24. Проверялось на первом запуске Linux-сборки
(`spok-linux-x64` из прогона CI) и на копии спеки в `~/Downloads/recmeet-openspec`.

---

## Короткая версия

Приложение падает при чтении спеки RecMeet. Непосредственная причина — обращение
по строковому ключу к значению, которое строкой и оказалось. Но настоящая причина
глубже: **в этой спеке два уровня вложенности, а Spok рассчитан на один**.

Spok обходит `openspec/changes/*` и считает change'ем каждый каталог. В RecMeet
на этом уровне лежат **группы** (`core`, `errors`, `subscriptions`, …), а
настоящие change'и — уровнем ниже. Их 83 штуки, и приложение до них не доходит.

Хорошая новость: **вложенные файлы Spok уже понимает**. Все 68 найденных
`redmine.yaml` change-уровня имеют `version: 4` и `stacks` словарём — ровно тот
формат, который читается сегодня. Имена артефактов тоже объявлены в схеме, а не
угаданы. Не хватает только обхода на уровень ниже и защиты от чужой формы.

---

## Как воспроизвели

Запуск Linux-сборки, подключение локального каталога спеки, шаг чтения:

```
[ERROR:flutter/runtime/dart_vm_initializer.cc(40)] Unhandled Exception:
type 'String' is not a subtype of type 'int' of 'index'
#0  PlatformFilesSource._loadRedmineLinks (platform_files_source.dart:541)
#1  PlatformFilesSource._loadChange        (platform_files_source.dart:453)
#2  PlatformFilesSource.loadChanges        (platform_files_source.dart:311)
#3  PlatformRepositoryImpl.load            (platform_repository_impl.dart:322)
#4  ConsoleBloc._onRefresh                 (console_bloc.dart:135)
```

Падение не связано с Linux: код чисто дартовый, платформенных веток в этом пути
нет. С тем же файлом приложение упало бы и на macOS. На Linux оно проявилось
просто потому, что там впервые открыли эту спеку.

## Непосредственная причина

`lib/data/sources/platform_files_source.dart`, строки 540–541:

```dart
final group = yaml['group'];
final members = group?['members'];   // ← падает здесь
```

`?['...']` защищает только от `null`. В RecMeet значение непустое, но и не
словарь:

```yaml
# openspec/changes/core/redmine.yaml
version: 2
group: core                    # ← строка, а не словарь
title: Core — сквозная архитектура
children:                      # ← вместо stacks
  testing_template: {…}
  design: {…}
  lead: {…}
  meeting: {…}
```

Индексация строки ключом `'members'` требует целочисленного индекса — отсюда
текст ошибки.

### Это не одна строка, а класс

В том же файле ещё восемь мест с тем же приёмом — обращение по ключу к результату
`loadYaml` без проверки типа:

| Строка | Выражение |
|---|---|
| 110, 117–122 | `yaml['artifacts']`, `artifact['id']`, `artifact['requires']` |
| 128 | `yaml['apply']?['instruction']` |
| 149–159 | `yaml['statuses']`, `yaml['sync']`, `status['id']` |
| 226, 235–240 | `yaml?['branches']`, `entry.value?['name']` |
| 291 | `build['version_code']` |
| 540–553 | `yaml['group']`, `group?['members']`, `group?['feature_sprint']` |

Показательно, что соседние места в том же методе защищены правильно —
`if (stacks is YamlMap)`, `members is YamlList`. Приём известен, но применён
не везде.

### Что важнее самого падения

Приложение **упало целиком** вместо того, чтобы показать спеку как
нераспознанную. Механика для этого уже есть: `SpecRecognition`, `formatWarning`,
экран «Что распознано» с перечнем «что понял, что нет». Вместо объяснения
пользователь получил закрытое окно — это прямо противоречит принципу
«не прятать, а объяснять».

## Настоящая причина: два уровня вместо одного

```
openspec/changes/
├── core/                        ← ГРУППА. Spok считает это change'ем
│   ├── redmine.yaml             version: 2 · group строкой · children
│   ├── README.md
│   ├── media-download/          ← НАСТОЯЩИЙ change
│   │   ├── redmine.yaml         version: 4 · change: core/media-download · stacks
│   │   ├── proposal.md
│   │   ├── system_design.md
│   │   ├── test_case.md
│   │   ├── specs/
│   │   ├── backend/tasks.md
│   │   └── frontend/tasks.md
│   └── … ещё 28 change'ей
├── errors/              25 change'ей
├── subscriptions/       23
├── admin-panel/          4
├── browser-extension/    2
└── archive/              4
```

Итого: **6 каталогов на верхнем уровне, 83 настоящих change'а под ними.**
Spok видит шесть «change'ей» и падает на первом же их `redmine.yaml`.

---

## Что Spok уже умеет — работы меньше, чем кажется

Это главный вывод разбора, и он определяет выбор варианта.

| Проверено | Результат |
|---|---|
| Версии вложенных `redmine.yaml` | **все 68 — `version: 4`**, а Spok поддерживает 3 и 4 |
| Форма `stacks` во вложенных | словарь — читается сегодняшним кодом |
| Имена файлов задач | `backend/tasks.md` объявлено в схеме как `generates` — не зашито в код |
| Имя файла дизайна | `system_design.md` — там же, в схеме |
| Имя схемы | `spec-driven-redmine`, то же, что у avtoto |

То есть **чтение самих change'ей переписывать не нужно**. Нужен обход на уровень
ниже и терпимость к файлу группы.

---

## Чем RecMeet отличается от наших двух спек

| | avtoto | avelacom | recmeet |
|---|---|---|---|
| Уровни в `changes/` | один | один | **два** |
| Группировка | каталог спринта | мастер-спека файлом | **каталог-группа внутри `changes/`** |
| Файл группы | `sprint.yaml` | `doc/<id>.md` | **`changes/<группа>/redmine.yaml`, version 2** |
| Файл задач | `tasks_ios.md` | `tasks_backend.md` | `backend/tasks.md` |
| Дизайн | `design.md` | `design.md` | `system_design.md` |
| Стеки | ios, android | backend | backend, frontend |

Последние три строки вопросов не вызывают: Spok берёт эти имена из схемы.
Проблема ровно в первых трёх.

## Варианты решения

### A. Только защита от формы

Общий помощник «значение по ключу, если узел словарь, иначе `null`», проведённый
через все девять мест. Неожиданная форма уходит в `formatWarning` и на экран
«Что распознано».

- **Даёт:** приложение перестаёт падать на любом YAML, включая ещё не встреченные
  спеки. Пользователь видит объяснение вместо закрытого окна.
- **Не даёт:** RecMeet по-прежнему не читается — покажет шесть пустых
  «change'ей» с пометкой о нераспознанном формате.
- **Объём:** S. Один helper, девять замен, три теста на кривой YAML.

### B. A + двухуровневый обход

Если в `changes/<X>/` нет признаков change'а (`proposal.md`), но есть вложенные
каталоги с ними — считать `X` группой, а вложенные каталоги — change'ами.

- **Даёт:** RecMeet открывается по-настоящему. 83 change'а, группы в селекторе,
  статусы из файлов version 4 — всё существующим кодом.
- **Риск:** признак «что считать группой» выводится эвристикой. Нужно правило,
  которое не сломает avtoto и avelacom — там вложенных каталогов с `proposal.md`
  нет, так что различение однозначное, но это надо закрепить тестом на всех трёх
  спеках.
- **Объём:** M.

### C. B + поддержка файла группы version 2

Читать `changes/<группа>/redmine.yaml`: `title`, `display_name`, `subtitle`,
`issue_id`, `children`.

- **Даёт:** у группы появляется человеческое имя («Core — сквозная архитектура»)
  вместо идентификатора каталога, и связь с корневой задачей Redmine.
- **Вопрос для обсуждения:** `children` — это не стеки в нашем понимании
  (`testing_template`, `design`, `lead`, `meeting`). Нужно решить, что это для нас
  и показываем ли мы их вообще.
- **Объём:** M, плюс неясность в `children`.

---

## Рекомендация

**Делать A немедленно и отдельно от остального.** Это не про RecMeet: любая
следующая незнакомая спека сегодня роняет приложение, а обещание продукта —
«работает с любой спекой». Защита от формы нужна независимо от того, будем ли
мы поддерживать двухуровневую структуру.

**B — следующим шагом, если RecMeet нужен как поддерживаемая спека.** Это
решение продуктовое, а не техническое: берём ли мы третью команду.

**C — после B и после ответа по `children`.** Без ответа он превратится в
угадывание, а это ровно то, чего продукт старается не делать.

---

## Что это меняет в плане работ

В `feature-plan.md` §2 «шестая стратегия из плана (ручная привязка change'ей
к группе)» стоит как не начатая, а трекерные стратегии — под гипотетическую
команду. Раньше был довод: ни одна из наших двух спек по трекеру не группируется,
значит строить и проверять не на чем.

**Этот довод снят.** Появилась третья живая спека с настоящей шестой стратегией —
группа как каталог. Это не гипотеза, а упавшее приложение и 83 change'а, которые
можно взять как проверочные данные.

Предложение: в блоке 6 «Этап 4 — модель» первой делать **группу-каталог**, а не
`trackerVersion` — она проверяется на реальных данных прямо сейчас.

## Как перепроверить самому

Все утверждения выше получены этими командами. Спека — в
`~/Downloads/recmeet-openspec`.

```bash
cd ~/Downloads/recmeet-openspec

# форма group в файлах верхнего уровня — причина падения
grep -A6 "^group:" openspec/changes/*/redmine.yaml | head -20

# сколько групп и сколько change'ей под каждой
for d in openspec/changes/*/; do
  n=$(find "$d" -maxdepth 1 -mindepth 1 -type d | wc -l)
  v=$(grep -m1 "^version:" "$d/redmine.yaml" 2>/dev/null | awk '{print $2}')
  printf "%-22s вложенных: %-3s version: %s\n" "$(basename $d)" "$n" "${v:-—}"
done

# версии вложенных файлов — все ли читаемые нами
grep -h "^version:" openspec/changes/*/*/redmine.yaml | sort | uniq -c

# состав настоящего change'а
ls openspec/changes/core/media-download/
cat openspec/changes/core/media-download/redmine.yaml | head -20

# имена артефактов берутся из схемы, а не из кода
grep -E "^  - id:|^    generates:" openspec/schemas/spec-driven-redmine/schema.yaml
```

В коде Spok:

```bash
sed -n '535,545p' lib/data/sources/platform_files_source.dart   # место падения
grep -n "is YamlMap\|is YamlList" lib/data/sources/platform_files_source.dart
```
