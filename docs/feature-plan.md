## 1. Распознавание спеки

Приложение не зашивает устройство спеки в код, а читает его: схему
(`openspec/schemas/*/schema.yaml`), семантику статусов (`openspec/redmine.yaml`),
стеки, команды и доступные фичи. Это фундамент — на нём стоят почти все
остальные фичи.

- [x] схема: артефакты, стеки, шаблон ветки change'а
- [x] семантика статусов из `sync.*` вместо русских строк в коде
- [x] команды с дедупом и источником (схема · `.claude` · зеркала ·
      `package.json` · `Makefile`)
- [x] фичи включаются по факту наличия данных
- [ ] правка распознанного человеком: стратегия, стеки, статусы, роли
      команд (экран настроек проекта)
- [ ] `openspec/redmine.yaml` нет вовсе — спросить статусы один раз,
      подставив список из `GET /issue_statuses.json`
- [ ] «не распознано»: честный список того, что понято и что нет,
      с кнопкой «Указать вручную»

## 2. Группировка работы

Группа — это спринт, мастер-спека, версия трекера или родительская задача.
От неё зависят экран группы, передача и селектор в шапке.

- [x] `sprintDir` — каталог со `sprint.yaml`
- [x] `masterDoc` — мастер-спека одним файлом
- [x] «вне групп» — плоский список, селектор скрыт
- [x] четыре варианта таблицы по числу стеков
- [x] подпись селектора по стратегии («Спринт» · «Мастер-спека» · …)
- [ ] `trackerVersion` — группировка по версии трекера
- [ ] `trackerParent` — по родительской задаче
- [ ] шестая стратегия из плана (ручная привязка change'ей к группе)
- [ ] порядок change'ей из `group.members`, когда он задан
- [ ] `WorkUnit` отдельным типом: сейчас единица работы — всегда change
